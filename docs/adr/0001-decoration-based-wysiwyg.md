# 用装饰实现实时样式，不写文本布局引擎

VibeMark 要实现"编辑区本身按 markdown 语法呈现样式"，而 keel 只给两个可编辑控件：`el.TextArea`（单一样式）与 `kit.CodeEditor`（装饰集合可设前景色、字重、斜体、下划线，不改字宽）。我们选择在 `kit.CodeEditor` 之上用 goldmark 解析源码、把样式区间翻成 `CodeDecoration`，而不是接管 Gio 的文本布局与光标去写一个真富文本编辑器。

## Consequences

- 收益：光标、选区、输入法、多光标、撤销、查找替换全部由 `CodeEditor` 承担，我们不写文本布局引擎。
- 代价：编辑区里字号无法放大（装饰不改字宽），所以标题只能加粗加色、真字号只出现在全屏预览里；这不是 Typora 式排版，是"半实时"。
- 代价：每次改动都要重建装饰，成本与文档长度成正比；大文件需要按实测阈值降级为只染色。

## Considered Options

- `el.TextArea` + 自绘样式：它只支持单一文本样式，整篇一个字号颜色，做不到行内加粗。
- 自研富文本编辑器：要接管 Gio 的文本布局、光标、输入法与选区，成本远高于 MVP，且等于重写 `CodeEditor` 已有的全部功能。

相关术语见 `GLOSSARY.md`（标记、装饰、淡化、半实时）。

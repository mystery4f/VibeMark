# 整篇一个编辑器，样式全靠装饰

## 背景

ADR-0002 用分块编辑做出接近 Typora 的视觉：非活动块交给 `ui/markdown` 渲染，活动块换成 `kit.CodeEditor`。代价是每个文本编辑行为都得在下游模拟，因为 keel 的编辑器只认它自己的整篇缓冲区：

- 跨块退格要在缓冲区首尾各放一个零宽守卫字符来嗅探（`blockGuard`），空块的退格还得单独认；
- 光标落点由 `SetCursor` 钳在 rune 范围内，点击渲染块只能把光标放到块首，再点一次才能定位；
- `SetValue` 清空撤销栈，而 keel 没有写缓冲区的接口，于是"整篇改写类"命令不断打断撤销；
- 用户在真实使用里连续报出跨块退格失效、空段落退格无反应、空段落全选（Ctrl+A）无效、守卫字符被顶进正文等一串缺陷，它们都源自同一层模拟。

## 决定

回到整篇一个 `kit.CodeEditor`，排版效果全部由 `CodeDecoration` 表达：

- 编辑器占满窗口（`Fill()`），文档不再拆块，没有活动块、守卫字符、整篇替换这类状态；
- `internal/mddoc.Decorations` 用 goldmark 解析整篇，把标题、强调、行内代码、链接、列表与引用标记转成装饰：整体色/字重/斜体交给 `CodeDecoration.Text`，标记符号用约 40% 不透明度淡化，不隐藏；
- 光标、选区、撤销、输入法、多光标、Enter/Shift+Enter/Backspace/Delete 全部交还 keel 的编辑器，窗口只注册改写整篇的命令（加粗、标题、代码围栏、粘贴、保存、预览、侧栏）；
- 预览仍用整篇 `ui/markdown`，进入预览和退出预览只切换视图。

## 后果

- 编辑行为是真的文本框行为：输入、换行、跨行退格、撤销、全选都由 keel 负责，不再有模拟层带来的边缘缺陷。
- 视觉退回 ADR-0001 的水平：标题是加粗加强调色而**不是标题字号**，标记只淡化而**不消失**——keel 装饰不改字形宽度，这是硬约束。
- 性能反而更好：整篇一个编辑器 20000 行一帧 0.097ms，单次键入 0.632ms（分块方案里 900 行的块一帧 43.8ms、单次键入 3.13ms）。
- 改写整篇的命令（加粗、标题、代码围栏、`SetValue` 路径）会让撤销历史从头开始：keel 没有暴露写底层的接口。
- 行号栏无法关闭（`ui/kit/code_editor_paint.go` 写死宽度），自带滚动条也无法隐藏——这是本决定最明显的视觉代价。
